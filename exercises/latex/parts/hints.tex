\section{Part 1}

\begin{description}[style=nextline, leftmargin=1.5em]
  \item[1.1] 紧凑构造函数写在 record 的大括号里面，形式是 \code{public Station { ... }}，没有参数列表。里面可以直接用 \code{name}、\code{availableBikes} 这些参数名。
  \item[1.3] 流水线的顺序：
\begin{plaincode}
stream()
  -> map(...)            转成 NearbyStation
  -> sorted(Comparator.comparingLong(NearbyStation::distanceMeters))
  -> limit(limit)
  -> toList()
\end{plaincode}
\code{limit} 参数检查要放在 Stream 前面，因为 \code{Stream.limit} 收到负数时抛的异常信息不清楚。
  \item[1.4] 可以连着写几个 \code{filter}。比如“如果打开了 requireBikes，就只保留有车的”，可以写成 \code{.filter(s -> !requireBikes || s.availableBikes() > 0)}。想一想为什么这样写是对的。
\end{description}

\section{Part 2}

\begin{description}[style=nextline, leftmargin=1.5em]
  \item[2.1 报错 No qualifying bean of type AppProperties] 说明容器里没有 \code{AppProperties} 这个 Bean。检查两处：\code{AppProperties} 上有没有 \code{@ConfigurationProperties(prefix = "app")}；\code{AppConfig} 上有没有 \code{@Configuration} 和 \code{@EnableConfigurationProperties(AppProperties.class)}。
  \item[2.2 嵌套对象是 null] 在 \code{AppProperties} 的 \code{jcdecaux} 和 \code{scraper} 两个参数前面加 \code{@DefaultValue}。
\end{description}

\section{Part 3}

\begin{description}[style=nextline, leftmargin=1.5em]
  \item[3.1 某个字段是 0 或 null] 说明 Jackson 没找到对应的 JSON 字段。检查 \code{@JsonProperty} 里的名字是否和 JSON 完全一致，以及 import 的是不是 \code{com.fasterxml.jackson.annotation.JsonProperty}。
  \item[3.3 报错 No further requests expected 或 URL 不匹配] 把报错信息里实际请求的 URL 和期望的 URL 逐个字符对比。常见问题：\code{path} 少了开头的 \code{/}，或者两个查询参数的顺序反了。
  \item[3.3 构造函数里 restClient 赋值] \code{this.restClient = builder.baseUrl(props.baseUrl()).build();}
\end{description}

\section{Part 4}

\begin{description}[style=nextline, leftmargin=1.5em]
  \item[4.4 派生查询的方法名] 拆开来看：\code{findFirst} + \code{By} + \code{IdNumber}（条件：id.number 等于参数）+ \code{OrderBy} + \code{IdLastUpdate} + \code{Desc}。
  \item[4.5 JPQL 写不出来] 照着知识点里“每个作者最新的书”改：实体是 \code{AvailabilityEntity}，分组字段是 \code{a.id.number}，比较的字段是 \code{a.id.lastUpdate}。
\end{description}

\section{Part 5}

\begin{description}[style=nextline, leftmargin=1.5em]
  \item[5.1 不知道从哪里开始] 一个 for 循环，两个计数器 \code{stationsSaved} 和 \code{availabilityInserted}。站点部分照着知识点里的 upsert 写；可用量部分：先用 \code{dto.lastUpdateInstant()} 判断是否为 null（是 null 就 \code{continue}），再 \code{new AvailabilityId(dto.number(), lastUpdate)}，用 \code{existsById} 判断。
  \item[5.3 @Scheduled 的写法] \code{@Scheduled(fixedDelayString = "${app.scraper.interval:5m}")}
\end{description}

\section{Part 6}

\begin{description}[style=nextline, leftmargin=1.5em]
  \item[6.1a] 第一步，把 \code{findLatestForAllStations()} 的结果转成 Map：
\begin{java}
Collectors.toMap(a -> a.getId().number(), Function.identity())
\end{java}
第二步：\code{stationRepository.findAll(Sort.by("number"))} 转成 Stream，\code{map} 里调用 \code{toStation(s, map.get(s.getNumber()))}。
  \item[6.1b] 先找站点，找不到就抛异常；再找最新的可用量，找不到就用 null：
\begin{java}
stationRepository.findById(number)
        .orElseThrow(() -> new StationNotFoundException(number));
availabilityRepository.findLatest(number).orElse(null);
\end{java}
  \item[6.3 404 测试过了，400 测试的 Content-Type 不对] 检查 \code{GlobalExceptionHandler} 是否继承了 \code{ResponseEntityExceptionHandler}。
  \item[FinalApplicationTest 失败] 找报错里 \code{Caused by:} 开头的最后一行，通常是 \code{No qualifying bean of type 'XXX'}，说明 XXX 这个类没有被 Spring 管理：检查它上面有没有 \code{@Service} 或 \code{@Component}。
\end{description}

\section{Part 7}

\begin{description}[style=nextline, leftmargin=1.5em]
  \item[7.1 import 找不到 JsonNaming] Jackson 3 的包：\code{tools.jackson.databind.annotation.JsonNaming} 和 \code{tools.jackson.databind.PropertyNamingStrategies}。注解写法：\code{@JsonNaming(PropertyNamingStrategies.SnakeCaseStrategy.class)}。
  \item[7.2 POST 的写法] 照着 Part 3 的 \code{fetchStations}，把 \code{get()} 换成 \code{post()}，\code{uri("/predict")}，加上 \code{.contentType(MediaType.APPLICATION_JSON)} 和 \code{.body(request)}，最后 \code{.body(ForecastResponse.class)} 拿到响应再取 \code{predictions()}。
  \item[7.2 状态码怎么拿] \code{onStatus} 的 lambda 里：\code{int status = res.getStatusCode().value();}
  \item[7.3] \code{@JsonInclude(JsonInclude.Include.NON_NULL)}，包是 \code{com.fasterxml.jackson.annotation}。
\end{description}

\section{Part 8}

\begin{description}[style=nextline, leftmargin=1.5em]
  \item[8.1 配置都从哪里取] 先 \code{ForecastProperties.Resilience r = properties.resilience();}，再用 \code{r.windowSize()}、\code{r.openFor()}、\code{r.maxAttempts()}、\code{r.retryWait()}。照着知识点里“支付接口”的例子填就行。
  \item[8.3 retryOnException] 参数是一个返回 boolean 的 lambda：\code{e -> e instanceof ForecastUnavailableException f && f.isRetryable()}。\code{instanceof} 后面直接写变量名 \code{f}，判断成功就能当 \code{ForecastUnavailableException} 用（Java 16 的模式匹配）。
  \item[8.2 怎么包] 先写 \code{Supplier<List<HourlyPrediction>> call = () -> client.predict(request);}，再 \code{CircuitBreaker.decorateSupplier(circuitBreaker, Retry.decorateSupplier(retry, call))}，然后在 try 里调用 \code{.get()}。
  \item[8.2 熔断测试的调用次数不对] 检查是不是把熔断器包在了里面、重试包在了外面。熔断器必须在外层。
  \item[FinalApplicationTest 报 No qualifying bean of type CircuitBreaker] \code{ForecastResilienceConfig} 上没有 \code{@Configuration}，或者方法上没有 \code{@Bean}。
\end{description}

\section{Part 9}

\begin{description}[style=nextline, leftmargin=1.5em]
  \item[9.1a 思路] \code{now} → \code{truncatedTo(ChronoUnit.HOURS)} 得到 \code{start} → 如果 \code{now.isAfter(start)} 就 \code{start = start.plusHours(1)} → \code{IntStream.range(0, hours).mapToObj(i -> 起点.plusHours(i)).toList()}。
  \item[9.1a 报错：lambda 里的变量必须是 final] \code{start} 在 \code{if} 里被重新赋值过，不能直接在 lambda 里用。先 \code{LocalDateTime first = start;}，lambda 里用 \code{first}。
  \item[9.1b 总车位数和当前车辆数] \code{station.totalStands()}、\code{station.availableBikes()}。
  \item[9.1c] \code{predictions.isEmpty()} 就是 degraded；预测列表用 \code{predictions.orElse(List.of())}。
\end{description}

\begin{description}[style=nextline, leftmargin=1.5em]

\section{Part 13}

\begin{description}[style=nextline, leftmargin=1.5em]
  \item[13.1a] 一行就能写完：
\begin{java}
return currentRepository.latest()
        .map(CurrentWeatherEntity::toSnapshot)
        .orElseGet(client::current);
\end{java}
注意是 \code{orElseGet}，用 \code{orElse(client.current())} 的话，就算数据库里有，也会先调用一次 OpenWeather。
  \item[13.1b 过滤“现在以后”] 先 \code{Instant now = Instant.now(clock);}，两处都用同一个 \code{now}。API 的结果用 \code{.filter(w -> !w.time().isBefore(now))}：“不早于”就是“不在它之前”，等于现在的那一档也保留。然后 \code{.limit(limit).toList()}。
  \item[13.3 比较器] \code{Comparator.comparing((WeatherSnapshot w) -> Duration.between(w.time(), target).abs()).thenComparing(WeatherSnapshot::time)}。\code{Duration} 可以直接比较大小。
  \item[13.2b 返回的是 500 而不是 503] 检查处理方法上有没有 \code{@ExceptionHandler(WeatherUnavailableException.class)}：只有 \code{@RestControllerAdvice} 不够，Spring 要靠这个注解才知道这个方法处理哪种异常。另外 \code{WeatherExceptionHandler} 不要继承 \code{ResponseEntityExceptionHandler}（原因见知识点）。
\end{description}
